## 3. Установка Tesseract OCR

`pytesseract` — только обёртка, сам движок ставится отдельно.

**Windows**
1. Установщик: <https://github.com/UB-Mannheim/tesseract/wiki> (например, `tesseract-ocr-w64-setup-5.x.x.exe`).
2. В разделе **Additional language data** отметить **Russian** (English обычно уже стоит).
3. Оставить путь по умолчанию `C:\Program Files\Tesseract-OCR`.

**Linux**

```bash
sudo apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
```

**macOS**

```bash
brew install tesseract tesseract-lang
```

**Проверка**

```bash
tesseract --version
tesseract --list-langs    # должны быть rus и eng
```

Если Tesseract установлен в нестандартное место — задайте путь переменной окружения:

```powershell
# Windows PowerShell
$env:TESSERACT_CMD = "D:\Tools\Tesseract-OCR\tesseract.exe"
```

```bash
# Linux / macOS
export TESSERACT_CMD=/opt/tesseract/bin/tesseract
```

### Принцип устройства

```text
main.py
  │  while True: await state_reader(ui)
  ▼
src/logic/uiStateReader.py
  │  читает состояние контролов (img_source.state, img_src_1/2, галочки)
  │  и вызывает нужный обработчик
  ├── ImageReader.images_update  → файлы  → cv_.match_fingerprints → cv_window.set_src
  ├── ImageReader.camera_update  → камера → temp PNG → cv_.match_fingerprints
  ├── ImageReader.screen_update  → экран  → temp PNG → cv_.match_fingerprints
  └── TextReader.*               → Tesseract → cv_window.txt
  ▼
src/ui/components/cvWindow.py  — обновляет ft.Image / ft.TextField
```

Ключевая идея: интерфейс **не содержит логики**, а `uiStateReader` **не знает
о разметке** — он просто читает значения контролов и пишет результат обратно.
Поэтому новый источник изображения добавляется одним `case` в `state_reader`.

## 6. Как работает программа

### 6.1. Цикл обновления

```python
# main.py
while True:
    try:
        await state_reader(ui)
    except Exception:
        traceback.print_exc()
        await asyncio.sleep(1)
    await asyncio.sleep(0.05)
```

`state_reader` вызывается ~20 раз в секунду. Каждый вызов:

1. берёт `ui.img_source.state` (`"load"` / `"camera"` / `"screen"`);
2. проверяет флаг `ui.imgs_loads.text_check.value`:
   * `False` → обычное сопоставление изображений (`ImageReader`);
   * `True` → распознавание текста (`TextReader`);
3. вызывает соответствующий обработчик.

Чтобы не пересчитывать одно и то же, у каждого режима есть кэш:

```python
@dataclass
class Cache:
    src_1, src_2          # какие файлы уже обработаны
    cap_num, cap          # номер и объект камеры
    textFl                # флаг текстового режима
    markers, unit_markers # состояние галочек
```

Если файлы и галочки не изменились — обработчик сразу выходит (сравнение
в `ImageReader.images_update`). В режимах камеры и экрана кадр меняется
каждый раз, поэтому сопоставление выполняется постоянно.

### 6.2. Сопоставление изображений (ЛР2)

Модуль `src/cv/cv_.py`, функция `match_fingerprints(img1_path, img2_path, markers, unit_markers, coef=0.7)`.

1. **`preprocess_fingerprint`**
   * файл читается через `imread()` (с поддержкой кириллицы в пути);
   * `cvtColor(...BGR2GRAY)` — перевод в оттенки серого;
   * `threshold(..., THRESH_BINARY_INV + THRESH_OTSU)` — бинаризация (инверсия,
     т.к. объект обычно темнее фона).

2. **`cv2.ORB_create()` → `detectAndCompute`**
   Возвращает ключевые точки `kp` и бинарные дескрипторы `des`.
   Если дескрипторов нет (пустое/однотонное изображение) — функция возвращает
   `0, None, []`, и окно просто не обновляется.

3. **`BFMatcher(NORM_HAMMING).knnMatch(des1, des2, k=2)`**
   Для каждой точки первого изображения находятся два лучших кандидата
   во втором. Норма Хэмминга — потому что дескрипторы ORB бинарные.

4. **Ratio-тест Лоу**
   ```python
   if m.distance < coef * n.distance:   # coef = 0.7
       good_matches.append(m)
   ```
   Пара считается надёжной, если она заметно лучше второго кандидата.
   Пары с одним кандидатом (`len(pair) < 2`) пропускаются — именно на них
   раньше падала распаковка `m, n`.

5. **Отрисовка** `cv2.drawMatches(...)` — два изображения рядом и линии между
   совпавшими точками. Флаги зависят от галочек:
   * «Отобразить маркеры» включена → `DRAW_RICH_KEYPOINTS` (окружности с
     размером и ориентацией);
   * выключена → `NOT_DRAW_SINGLE_POINTS` (только линии совпадений).

6. **Возврат** `(len(good_matches), match_img, points)`, где `points` —
   координаты совпавших точек первого изображения (печатаются в консоль: `pr [...]`).

Файл `src/cv/cv.py` — та же задача на **SIFT** + FLANN (более устойчив к масштабу
и повороту, но медленнее). Сейчас `uiStateReader` подключает `cv_` (ORB);
чтобы переключиться на SIFT, достаточно поменять импорт:

```python
# from ..cv.cv_ import match_fingerprints
from ..cv.cv import match_fingerprints
```

### 6.3. Источники кадра

| Источник | Как получается кадр | Особенности |
|---|---|---|
| `load` | файл, выбранный в `LoadImgsBlock` | обрабатывается один раз; повторно — только при смене файла/галочек |
| `camera` | `cv2.VideoCapture(cap_num).read()` | камера открывается лениво и один раз; при ошибке чтения кадр пропускается |
| `screen` | `pyautogui.screenshot()` (или `PIL.ImageGrab`) | снимок экрана; если графическая сессия недоступна — сообщение в поле результата |

Кадр/скриншот сохраняется во временный PNG (`frameToPath.py`, `screenToPath.py`),
потому что `match_fingerprints` и Tesseract работают с путями к файлам.
Временные каталоги создаются через `tempfile.mkdtemp()` — в них не бывает проблем
с кодировкой.

### 6.4. Распознавание текста (ЛР3)

Модуль `src/cv/tesseract.py`.

```python
async def image_to_string(path, lang="rus+eng"):
    return await asyncio.to_thread(sync_image_to_string, path, lang)
```

* `asyncio.to_thread` — Tesseract работает секундами, его нельзя вызывать
  в событийном цикле напрямую.
* Путь к `tesseract.exe` определяется при импорте (`find_tesseract()`):
  `TESSERACT_CMD` → `PATH` (`shutil.which`) → стандартные каталоги Windows/Linux/macOS.
* Язык проверяется по фактически установленным пакетам (`get_languages()`):
  если `rus` не установлен, останется `eng`, и OCR не упадёт с
  `Failed loading language 'rus'`.
* Распознанный текст печатается в консоль (требование задания) и возвращается
  в `TextReader`, который кладёт его в `ui.cv_window.txt`.

Пока идёт распознавание, в поле выводится `"Ждите... =)"`, затем — результат.
Если текста нет, показывается `*нет текста*`.

### 6.5. Отображение картинки

`ft.Image` не умеет показывать произвольный путь к файлу (в браузере — точно,
на десктопе зависит от платформы). Поэтому все изображения передаются как
base64-строка:

```python
# src/utils/cv2_to_flet_base64.py
BGR → RGB → PIL.Image → PNG в BytesIO → base64
ui.cv_window.set_src(img_base64)   # внутри: self.pic.src = src; self.update()
```

## 7. Как пользоваться

### 7.1. Сопоставление изображений

1. Слева отметьте **«Загрузить изображение»**.
2. Выберите **изображение сцены** и **изображение объекта** (кнопки «Выберите файл»).
3. Правая панель покажет:
   * картинку с линиями совпадений и ключевыми точками;
   * количество совпадений — в консоли (`pr [...]` — координаты точек).
4. Галочка **«Отобразить маркеры»** переключает вид (точки/только линии).

### 7.2. Веб-камера

1. Отметьте **«Включить вебкамеру»**.
2. Обязательно выберите **изображение объекта** — именно его программа будет
   искать в кадре.
3. В окне — живой кадр с линиями совпадений. Если камера не открылась,
   проверьте, не занята ли она другим приложением (Zoom, Teams, браузер).

Номер камеры берётся из поля рядом с галочкой (`0` — камера по умолчанию;
поле неактивно, значение задаётся в коде/`Cap`).

### 7.3. Снимок экрана

1. Отметьте **«Снимок экрана»**.
2. Выберите **изображение объекта**.
3. В окне — снимок монитора с результатом поиска.

На Linux без графической сессии снимок экрана недоступен — в поле результата
появится сообщение об этом, остальные режимы продолжат работать.

### 7.4. Распознавание текста

1. Отметьте галочку **«Распознать текст»**.
2. Выберите изображение (используется **первое** изображение — «сцена»).
3. Правая панель: сверху картинка, ниже — распознанный текст.
   Он же печатается в консоль.
4. Язык по умолчанию `rus+eng`; чтобы изменить, передайте другой `lang`
   в `image_to_string` (например, `"rus"` или `"eng"`).

## 8. Версии библиотек

`requirements.txt`:

| Пакет | Версия | Зачем |
|---|---|---|
| `flet` | `1.0.5` | GUI-фреймворк |
| `flet-desktop` | `1.0.5` | настольный клиент (без него `ft.run` не откроет окно) |
| `numpy` | `2.4.6` | массивы для OpenCV |
| `opencv-contrib-python` | `5.0.0.93` | ORB/SIFT, бинаризация, `drawMatches` |
| `pillow` | `13.0.0` | открытие изображений для Tesseract |
| `pytesseract` | `0.3.13` | обёртка Tesseract OCR |
| `pyautogui` | `0.9.54` | снимок экрана (импортируется лениво) |

Почему именно `==`: раньше в файле стояли имена без версий, pip ставил самые
свежие пакеты, и обновление Flet ломало код. С фиксированными версиями
окружение воспроизводимо.

Если нужна другая среда:

* Python 3.10 → `numpy==2.3.3`, `pillow==11.3.0`;
* Python 3.14 → набор из таблицы подходит как есть;
* OpenCV 4.x → `opencv-contrib-python==4.10.0.84` (ORB/SIFT работают так же).

## 9. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `ModuleNotFoundError: No module named 'flet'` | не активировано окружение | `pip install -r requirements.txt` |
| Окно не открывается, в консоли `flet-desktop not installed` | нет настольного клиента | `pip install flet-desktop==1.0.5` |
| `ImportError: libGL.so.1` (Linux) | нет системной библиотеки | `sudo apt install libgl1` |
| В окне пусто, ошибок нет | старый `cv2.imread` на пути с кириллицей | теперь используется `src/utils/imread.py`; проверьте, что запущен актуальный код |
| Камера не открывается | занята другим приложением | закрыть Zoom/Teams/браузер, перезапустить программу |
| Камера «занята» после закрытия окна | процесс не завершился | программа освобождает камеру в `page.on_close` |
| «Tesseract OCR не найден» | не установлен / не в `PATH` | см. [раздел 3](#3-установка-tesseract-ocr), задать `TESSERACT_CMD` |
| OCR вернул пустой текст | нет языкового пакета или мелкий текст | установить `rus`/`eng`, взять изображение крупнее |
| Ошибка `not enough values to unpack` | старый код и `knnMatch` | исправлено в `cv.py`; обновите файлы из репозитория |
| Снимок экрана не работает (Linux) | нет графической сессии | используйте режимы «файл» или «камера» |
| Программа «подвисает» на больших фото | ORB/SIFT считаются в цикле обновления | уменьшите изображения или используйте файлы меньшего размера |
