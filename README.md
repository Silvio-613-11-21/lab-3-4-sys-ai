# СИИ · Лабораторные работы №2 и №3

Приложение на **Python + Flet + OpenCV**, которое объединяет две лабораторные работы
по системам искусственного интеллекта:

| Лабораторная | Что делает программа |
|---|---|
| **№2** — поиск устойчивых признаков изображения | Находит изображение-образец на статичной сцене **и** в потоке с веб-камеры/экрана. Ключевые точки SIFT/ORB → дескрипторы → ratio-тест Лоу → гомография (RANSAC) → рамка найденного объекта. |
| **№3, часть 1** — контурный анализ | Полный пайплайн: серое → размытие → бинаризация → морфология → `findContours` → фильтрация → **уравнивание контуров** → сравнение по **NSP** с перебором циклических сдвигов (ВКФ) → рамки и подписи. Каждый шаг виден отдельной картинкой. |
| **№3, часть 2** — Tesseract OCR | Распознавание печатного текста на русском и английском, вывод текста в консоль **и** на выходное изображение. |

## 1. Почему программа «перестала работать» и что исправлено

Исходная версия действительно была рабочей — до определённого момента. Ниже разбор
конкретных причин «внезапной поломки» и того, что сделано в этой версии.
Каждый пункт — это реальный дефект из исходного кода, а не абстрактное «обновилось окружение».

### 1.1. Незакреплённые версии библиотек — главная причина

В старом `requirements.txt` были просто имена пакетов:

```text
flet
numpy
opencv-contrib-python
pyautogui
pillow
pytesseract
```

`pip install -r requirements.txt` ставит **самые свежие** версии. Когда Flet перешёл
с ветки `0.2x` на `1.0`, изменился публичный API:

* `ft.Button(text=...)` → `ft.Button(content=...)`;
* `ft.FilePicker().pick_files(...)` стал асинхронным и возвращает список файлов;
* `page.overlay.append(file_picker)` больше не нужен — сервисы регистрируются через `page.services`;
* часть констант (`ft.ImageFit`, `ft.Font`) переименована/удалена.

Код, написанный под `0.28`, на `1.0` падает при первом же обращении к несуществующему
параметру. Снаружи это выглядит как «вчера работало — сегодня нет».

**Исправлено:** все версии зафиксированы через `==` (см. [раздел 4](#4-зависимости-и-версии)),
а код написан под конкретную версию Flet 1.0.5.

### 1.2. Жёсткий путь к Tesseract ломал импорт модуля

```python
pytesseract.pytesseract.tesseract_cmd = r"c:\Program Files\Tesseract-OCR\tesseract.exe"
```

Путь был прописан под одну конкретную машину. На другой машине, после переустановки
Tesseract или просто при 64-битной версии в `Program Files (x86)` — OCR не работает,
а если Tesseract не установлен вовсе, `pytesseract` бросает исключение при первом вызове
и всё приложение выглядит «сломанным».

**Исправлено:** `src/core/ocr.py` сам ищет Tesseract (переменная `TESSERACT_CMD`,
`PATH`, стандартные каталоги Windows/Linux/macOS), кэширует результат и сообщает
пользователю понятным текстом, чего не хватает. Ошибка OCR больше не «убивает» окно.

### 1.3. `pyautogui` импортировался на верхнем уровне

```python
import pyautogui as pui
```

`pyautogui` при импорте обращается к X-серверу (на Linux) и подтягивает зависимости,
которые не собираются на новом Python. Итог: программа не стартует целиком, хотя
«снимок экрана» — второстепенная функция.

**Исправлено:** снимок экрана делается через `mss` (лёгкая кроссплатформенная
библиотека), импорт ленивый, есть резервные варианты (`PIL.ImageGrab`), а если экран
недоступен — приложение продолжает работать без этой функции.

### 1.4. `knnMatch` иногда возвращает одну пару → `ValueError`

```python
matches = flann.knnMatch(des1, des2, k=2)
good_matches = [m for m, n in matches if m.distance < coef * n.distance]
```

`knnMatch(k=2)` **не гарантирует** две пары: если во втором изображении меньше двух
дескрипторов, для некоторых точек вернётся список из одного элемента. Распаковка
`for m, n in matches` в этот момент падает с
`ValueError: not enough values to unpack (expected 2, got 1)`.

Именно такой характер ошибки создаёт эффект «раньше работало»: на одних картинках
пар всегда две, на других — нет.

**Исправлено:** `ratio_test()` в `src/core/features.py` проверяет длину пары и
защищается от нулевой дистанции.

### 1.5. Функция возвращала разное число значений

```python
if img1_bin is None or img2_bin is None:
    return 0, None          # 2 значения
...
return len(good_matches), match_img, points   # 3 значения
```

Вызывающий код всегда распаковывал три значения. Любое нечитаемое изображение
(например, путь с кириллицей — см. следующий пункт) давало
`ValueError: not enough values to unpack (expected 3, got 2)`.

**Исправлено:** единый тип результата — датакласс `MatchResult`, в котором есть
и статус, и картинка, и все метрики.

### 1.6. Кириллица в путях: `cv2.imread` молча возвращает `None`

`cv2.imread("C:\\Users\\Иван\\Downloads\\фото.jpg")` на Windows возвращает `None` —
функция не поддерживает не-ASCII пути. Ошибки нет, просто пустое окно.

**Исправлено:** `imread_unicode()` / `imwrite_unicode()` в `src/core/image_io.py`
читают файл через `numpy.fromfile` + `cv2.imdecode` (и `PIL` как резерв), а пишут через
`cv2.imencode` + `tofile`. Покрыто тестом `test_roundtrip_with_cyrillic_path`.

### 1.7. Камера не освобождалась, а `VideoCapture` создавался как поле класса

```python
@dataclass
class Cache():
    cap = cv2.VideoCapture(cap_num)     # создаётся один раз при импорте модуля
```

Плюс `reset_cap()` создавал новый `VideoCapture`, не освобождая старый. Через
несколько переключений камеры/перезапусков драйвер отказывал: `cap.read()` начинал
возвращать `False`, окно показывало последний кадр — «программа зависла».

**Исправлено:** `src/core/camera.py` — отдельный класс `CameraStream` с потоком чтения,
корректным `release()`, перезапуском и освобождением ресурса при закрытии окна
(`page.on_close`).

### 1.8. Всё компьютерное зрение выполнялось в UI-потоке

```python
while True:
    await state_reader(ui)
    await asyncio.sleep(0.05)
```

SIFT на кадре 1280×720 занимает десятки-сотни миллисекунд, `cap.read()` — блокирующий
вызов. Пока идёт обработка, окно не реагирует на клики; при накоплении задержек
Flet-клиент отваливается по таймауту — снаружи это «программа перестала работать».

**Исправлено:** тяжёлые операции вынесены из UI-потока:

* статичная обработка — `asyncio.to_thread(...)`;
* видеопоток — `LiveProcessor` (фоновый поток, который всегда держит только
  **последний** готовый кадр);
* UI забирает свежий результат 20 раз в секунду и никогда не ждёт вычислений.

### 1.9. Мелкие, но заметные дефекты

| Было | Стало |
|---|---|
| `cv2.putText` с русским текстом → `?????` | `src/core/drawing.py` рисует текст через Pillow с настоящим TTF-шрифтом |
| `pyproject.toml` требовал `python >= 3.14`, а колёса части библиотек под 3.14 отсутствовали | `>=3.11,<3.15`, версии зафиксированы |
| `requirements.txt` с хвостовыми пробелами и закомментированными пакетами | аккуратный файл с комментариями и точными версиями |
| Изображение в UI передавалось в исходном размере (base64 на десятки МБ) | перед отправкой в UI картинка ужимается до 1100 px по большей стороне |
| Отсутствие SURF «валило» программу | `surf_available()` реально проверяет сборку; при недоступности — SIFT/ORB и подсказка в интерфейсе |
| `findContours` на тёмном тексте по белому фону давал одну рамку вокруг всего листа | авто-инверсия полярности в `binarize()` |
| Нет обработки ошибок: любое исключение = закрытое окно | `try/except` на каждом действии + журнал + всплывающие сообщения |

## 2. Быстрый старт

### 2.1. Требования

* **Python 3.11 – 3.14** (проверено на 3.11 и 3.14).
* Windows 10/11, Linux или macOS.
* Веб-камера — опционально (для режима реального времени).
* Tesseract OCR — опционально (только для режима распознавания текста).

### 2.2. Установка

```bash
# 1. Клонировать репозиторий и перейти в него
git clone <адрес-репозитория>
cd lab-3-4-sys-ai

# 2. Создать виртуальное окружение
python -m venv .venv

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
# Windows (cmd)
.venv\Scripts\activate.bat
# Linux / macOS
source .venv/bin/activate

# 3. Установить зависимости (версии уже зафиксированы)
pip install -r requirements.txt
```

> **Только Linux:** OpenCV требует системную библиотеку `libGL`.
> `sudo apt install libgl1 libglib2.0-0`

### 2.3. Запуск

```bash
python main.py
```

Откроется настольное окно приложения.

Дополнительные варианты:

```bash
python main.py --web      # открыть в браузере на http://127.0.0.1:8550
pytest                    # прогнать автотесты
python tools/make_samples.py   # перегенерировать демонстрационные картинки
```

### 2.4. Переменные окружения (необязательно)

| Переменная | Зачем |
|---|---|
| `TESSERACT_CMD` | Явный путь к `tesseract.exe`, если автопоиск не сработал |

Пример для Windows:

```powershell
$env:TESSERACT_CMD = "C:\Program Files\Tesseract-OCR\tesseract.exe"
```

## 3. Установка Tesseract OCR

`pytesseract` — только обёртка; саму программу Tesseract нужно установить отдельно.

### Windows

1. Скачать установщик: <https://github.com/UB-Mannheim/tesseract/wiki>
   (файл вида `tesseract-ocr-w64-setup-5.x.x.exe`).
2. При установке в разделе **Additional language data** отметить **Russian**
   (и **English**, он обычно уже включён).
3. Установить в `C:\Program Files\Tesseract-OCR` — путь по умолчанию, программа найдёт его сама.
4. Если ставили в другое место — задать переменную окружения `TESSERACT_CMD`.

### Linux (Debian/Ubuntu)

```bash
sudo apt update
sudo apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
```

### macOS

```bash
brew install tesseract
brew install tesseract-lang     # языковые пакеты, включая rus
```

### Проверка

```bash
tesseract --version
tesseract --list-langs      # должны быть rus и eng
```

В самой программе есть кнопка **«Проверить Tesseract»** и **«Проверить окружение»** —
они показывают найденный путь, версию и доступные языки.

## 4. Зависимости и версии

Содержимое `requirements.txt`:

| Пакет | Версия | Зачем нужен |
|---|---|---|
| `flet` | `1.0.5` | GUI-фреймворк (Python-бэкенд + Flutter-клиент) |
| `flet-desktop` | `1.0.5` | Настольный клиент. **Без него `ft.run(main)` не откроет окно** — это единственный обязательный «спутник» Flet для десктопа |
| `opencv-contrib-python` | `5.0.0.93` | SIFT/ORB, `findContours`, морфология, гомография, `matchShapes`. Contrib-сборка нужна ради `xfeatures2d` (SURF), хотя в текущих колёсах SURF отключён по патентным причинам |
| `numpy` | `2.4.6` | Массивы, на которых работает OpenCV |
| `pillow` | `13.0.0` | Отрисовка подписей с кириллицей, панель OCR, конвертации |
| `pytesseract` | `0.3.13` | Обёртка над Tesseract OCR |
| `mss` | `10.2.0` | Кроссплатформенный снимок экрана |

Дополнительно для разработки (`requirements-dev.txt`): `pytest==9.1.1`.

### Две важные оговорки

1. **`opencv-contrib-python` нельзя ставить одновременно с `opencv-python`** — это
   конфликтующие пакеты с одинаковым именем модуля `cv2`. Если раньше ставили
   `opencv-python`, сначала удалите его:
   ```bash
   pip uninstall opencv-python opencv-contrib-python
   pip install -r requirements.txt
   ```
2. **SURF.** В предсобранных колёсах OpenCV 5 функция `cv2.xfeatures2d.SURF_create`
   присутствует, но выбрасывает ошибку:
   `This algorithm is patented and is excluded in this configuration`.
   Программа это определяет (`surf_available()`), не включает SURF в список детекторов
   и показывает подсказку. Для ЛР2 этого достаточно: SIFT покрывает всю теорию из методички,
   ORB — быстрый вариант для видеопотока.

Альтернативные наборы версий (если нужна другая среда):

* Python 3.10 → `numpy==2.3.3`, `pillow==11.3.0`, остальное без изменений;
* OpenCV 4.10 → `opencv-contrib-python==4.10.0.84` (SIFT/ORB работают так же).

## 6. Архитектура и поток данных

### 6.1. Статичное изображение (ЛР2 и ЛР3)

```text
[диалог выбора файла]
        │  путь к файлу (может содержать кириллицу)
        ▼
ImageCache.get(path)  ──────────────► src/core/image_io.imread_unicode
        │  numpy BGR-массив                       (imdecode + PIL fallback)
        ▼
asyncio.to_thread(обработка)          ← фон, интерфейс не замерзает
        │
        ├── ЛР2: find_object(sample, scene, params) → MatchResult
        │        └── картинка с линиями совпадений и рамкой
        │
        ├── ЛР3: analyze_contours(scene, reference, params) → ContourResult
        │        └── 9 шагов обработки, каждый со своей картинкой
        │
        └── OCR: recognize(image, lang) → OcrResult
                 └── картинка с рамками слов и панелью текста
        ▼
to_data_uri(image)  →  "data:image/png;base64,…"
        ▼
ft.Image.src  →  Flutter-клиент рисует картинку
```

### 6.2. Видеопоток (ЛР2, режим реального времени)

```text
   ┌───────────────────────┐        ┌──────────────────────────┐
   │ CameraStream (Thread) │        │ LiveProcessor (Thread)   │
   │  cap.read() в цикле   │ кадр   │  1. взять свежий кадр    │
   │  хранит последний     │───────►│  2. find_object(...)     │
   │  кадр + release()     │        │  3. to_data_uri(...)     │
   └───────────────────────┘        │  4. сохранить «последний»│
                                    └────────────┬─────────────┘
                                                 │ latest()
   ┌─────────────────────────────────────────────▼─────────────┐
   │ UI: _refresh_loop() — 20 раз/с, event loop asyncio         │
   │ берёт ТОЛЬКО свежий результат и обновляет ft.Image.src     │
   └────────────────────────────────────────────────────────────┘
```

Почему так, а не «в лоб»:

* камера отдаёт 30 кадров/с, SIFT обрабатывает 3–10 кадров/с — без буфера «последний
  кадр» очередь росла бы бесконечно;
* обработка в отдельном потоке не блокирует кнопки и прокрутку;
* UI обновляется по таймеру, а не по факту готовности кадра — значит, задержка не
  накапливается.

### 6.3. Жизненный цикл ресурсов

| Ресурс | Кто владеет | Когда освобождается |
|---|---|---|
| `cv2.VideoCapture` | `CameraStream` | `CameraStream.stop()` — при остановке потока и в `page.on_close` |
| Потоки `Thread` | `CameraStream`, `LiveProcessor` | `daemon=True` + явный `join(timeout=…)` |
| Кэш картинок | `ImageCache` | Не более 32 записей, вытеснение FIFO |
| Файлы результатов | Пользователь | Пишутся в `results/` по кнопке «Сохранить результат» |

## 7. Как устроен поиск объекта (ЛР2)

Модуль: `src/core/features.py`. Ключевая функция — `find_object(sample, scene, params)`.

### 7.1. Шаги алгоритма

1. **Предобработка** (`_preprocess`).
   Изображение переводится в оттенки серого. Дополнительно можно включить:
   * `CLAHE` — выравнивание локального контраста (полезно при неравномерном свете);
   * бинаризацию Оцу — для изображений с чётким контрастом (текст, печати, отпечатки).

2. **Детектор и дескрипторы** (`_create_detector`).
   * **SIFT** — 128-мерные вещественные дескрипторы, инвариантен к масштабу и повороту,
     наиболее устойчив к искажениям. Основной вариант.
   * **SURF** — 64-мерные вещественные дескрипторы, быстрее SIFT; доступен только
     в сборках без патентных ограничений (проверяется через `surf_available()`).
   * **ORB** — бинарные дескрипторы (норма Хэмминга), очень быстрый, удобен для потока.

3. **Сопоставление** (`_match_descriptors`).
   Для вещественных дескрипторов — `FlannBasedMatcher` (KD-дерево), для ORB —
   `BFMatcher(NORM_HAMMING)`. В обоих случаях `knnMatch(k=2)` — по два лучших
   кандидата на каждую точку. При проблемах с FLANN код автоматически откатывается
   на `BFMatcher`.

4. **Ratio-тест Лоу** (`ratio_test`).
   Пара `(m, n)` принимается, если `m.distance < ratio * n.distance`.
   Смысл: совпадение должно быть **заметно лучше** второго кандидата. При `ratio = 0.75`
   отбрасывается значительная часть случайных пар, и остаются характерные точки.
   Пара с единственным кандидатом или нулевой дистанцией безопасно пропускается
   (это была одна из причин падений в старой версии).

5. **Проверка геометрии — гомография + RANSAC**.
   ```python
   H, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0)
   inliers = int(mask.sum())
   ```
   Гомография описывает проективное преобразование «образец → сцена». RANSAC ищет
   такую матрицу, которую подтверждает максимальное число пар, а «выбросы» (ложные
   совпадения) помечаются нулями в `mask`. **Число inliers — главный критерий
   «объект найден»**, по умолчанию нужно ≥ 6.

6. **Рамка объекта**.
   Четыре угла образца преобразуются матрицей `H`:
   ```python
   corners = cv2.perspectiveTransform(corners, H)
   ```
   Полученный четырёхугольник рисуется на сцене. Дополнительно проверяется
   «вменяемость» рамки (`_box_is_sane`): если гомография «взорвалась» и рамка
   покрывает почти весь кадр — она не рисуется, чтобы не вводить в заблуждение.

7. **Отрисовка** (`_draw_matches`).
   `cv2.drawMatches` рисует обе картинки и линии между совпавшими точками.
   Флаги зависят от настроек интерфейса:
   * «Показывать ключевые точки» + «Соединять подобные маркеры» → `DRAW_RICH_KEYPOINTS`
     (окружности с размером и ориентацией);
   * показывать точки без соединения → `DEFAULT`;
   * не показывать → `NOT_DRAW_SINGLE_POINTS`.
   Итоговый статус («ОБЪЕКТ НАЙДЕН: 142 устойчивых совпадений») рисуется в левом
   верхнем углу с поддержкой кириллицы.

### 7.2. Что возвращает `find_object`

```python
MatchResult(
    found=True,                     # подтверждено гомографией
    message="ОБЪЕКТ НАЙДЕН: 142 устойчивых совпадений",
    details=[...],                  # строки для панели «Подробности»
    match_count=167,                # пар после ratio-теста
    inlier_count=142,               # подтверждено RANSAC
    keypoints_sample=..., keypoints_scene=...,
    elapsed_ms=358.2,
    image=<картинка с линиями и рамкой>,
    homography=<матрица 3x3>,
    box=<4 угла объекта на сцене>,
)
```

Тип результата фиксирован — никаких «то 2 значения, то 3».

### 7.3. Настройки, доступные из интерфейса

| Параметр | По умолчанию | На что влияет |
|---|---|---|
| Детектор | SIFT | скорость/точность |
| Порог ratio | 0.75 | меньше — строже, меньше ложных пар |
| Максимум ключевых точек | 2000 | ограничение времени обработки |
| Бинаризация Оцу | выкл. | для высококонтрастных снимков (текст, отпечатки) |
| CLAHE | вкл. | устойчивость к неравномерному освещению |
| Показывать ключевые точки | вкл. | читаемость картинки |
| Соединять подобные маркеры | выкл. | `DRAW_RICH_KEYPOINTS` |

## 8. Как устроен контурный анализ (ЛР3, часть 1)

Модуль: `src/core/contours.py`. Ключевая функция — `analyze_contours(scene, reference, params)`.

### 8.1. Пайплайн (9 шагов, каждый виден в интерфейсе)

| № | Ключ шага | Что делается | Функция OpenCV |
|---|---|---|---|
| 1 | `source` | исходное изображение | — |
| 2 | `gray` | перевод в оттенки серого | `cvtColor` |
| 3 | `blur` | подавление шума | `GaussianBlur` (нечётное ядро) |
| 4 | `binary` | бинаризация + авто-инверсия полярности | `threshold(OTSU)` / `adaptiveThreshold` |
| 5 | `morph` | удаление шумов | `morphologyEx` (OPEN + CLOSE) |
| 6 | `contours` | поиск контуров | `findContours(RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)` |
| 7 | `filtered` | фильтрация | `contourArea`, `arcLength`, `boundingRect` |
| 8 | `equalized` | **уравнивание** контуров | собственная `resample_contour` |
| 9 | `final` | результат: рамки, подписи, NSP | `rectangle`, `polylines`, Pillow-текст |

### 8.2. Авто-инверсия полярности

У метода Оцу нет понятия «объект/фон»: он просто делит яркости на две группы. Для
тёмного текста на белой бумаге «объектом» окажется фон, и `findContours` вернёт одну
рамку вокруг всего листа — классическая ошибка.

```python
object_ratio = float(np.mean(binary > 0))
if object_ratio > 0.5:          # «объекта» больше половины кадра
    binary = cv2.bitwise_not(binary)
```

Флаг `invert` позволяет задать полярность вручную, `auto_invert` (по умолчанию
включён) подбирает её автоматически.

### 8.3. Фильтрация контуров

`filter_contours()` отбрасывает:

* слишком маленькие (`area < min_area_ratio × площадь кадра`, по умолчанию 0.2 %);
* слишком большие (`area > max_area_ratio × площадь кадра`);
* короткие (`perimeter < min_perimeter`);
* вырожденные и «полоски» (`aspect > 25` или `< 1/25`).

Оставшиеся сортируются по площади — крупнейший считается главным объектом.

### 8.4. Уравнивание контуров (ресэмплинг)

Контуры реальных объектов имеют разную длину, а скалярное произведение определено
только для векторов одинаковой размерности. Поэтому все контуры приводятся к одной
длине `k` (по умолчанию 64):

```python
def resample_contour(points, count):
    # 1. длины сегментов и накопленная длина дуги
    # 2. count целей, равномерно распределённых по периметру
    # 3. линейная интерполяция внутри нужного сегмента
```

Если контур длиннее `k` — это прореживание, если короче — интерполяция. Оба случая
описаны в методичке как «уравнивание». Результат проверяется тестами:
`test_resample_returns_requested_number_of_points`, `test_resample_is_uniform_in_arc_length`.

### 8.5. Вектор-контур и NSP

Контур переводится в последовательность элементарных векторов (комплексных чисел):

```python
def contour_to_ev(points):
    shifted = np.roll(points, -1, axis=0)
    vectors = shifted - points
    return vectors[:, 0] + 1j * vectors[:, 1]
```

Скалярное произведение и нормированное скалярное произведение (NSP):

```python
(G, K) = Σ ev_Gi · conj(ev_Ki)
NSP    = (G, K) / (|G| · |K|)
```

Свойства, которые используются в программе:

* `|NSP| = 1` ⇔ контуры отличаются только масштабом и/или поворотом;
* `NSP` не зависит от выбора стартовой точки **при переборе сдвигов** (ВКФ);
* `arg(NSP)` — оценка угла поворота одного контура относительно другого.

### 8.6. ВКФ: перебор циклических сдвигов

```python
def compare_contours(reference, candidate):
    for direction in (1, -1):          # обход контура может быть в любую сторону
        for shift in range(count):     # все варианты стартовой точки
            value = scalar_product(ev_reference, np.roll(sequence, shift))
            score = abs(value)         # |NSP|
```

Дополнительно считается `cv2.matchShapes` (моменты Ху) — независимая метрика
сходства форм, которая выводится в подписи как `Hu=…`. Чем меньше, тем похожее.

Интерпретация в интерфейсе:

| `|NSP|` | Цвет рамки | Смысл |
|---|---|---|
| ≥ 0.90 | зелёный | практически та же форма |
| 0.70 – 0.90 | жёлтый | похожая форма |
| < 0.70 | красный | форма отличается |

### 8.7. Эталонный контур

* если пользователь выбрал отдельное изображение-эталон — из него извлекается
  крупнейший контур и уравнивается;
* иначе эталоном становится самый крупный контур самой сцены (тогда `#1` всегда
  имеет `NSP = 1.00` — это удобная проверка работоспособности).

### 8.8. Что возвращает `analyze_contours`

```python

    contours=[ContourInfo(index=1, area=..., perimeter=..., bbox=...,

                          angle=-4.7, hu_score=0.13), ...],
    image=<итоговая картинка>,
```

## 9. Как устроен OCR (ЛР3, часть 2)

Модуль: `src/core/ocr.py`.

### 9.1. Поиск Tesseract

`find_tesseract()` перебирает кандидатов в таком порядке:

1. переменная окружения `TESSERACT_CMD`;
2. уже установленный `pytesseract.pytesseract.tesseract_cmd`;
3. `shutil.which("tesseract")` (то есть `PATH`);
4. стандартные пути Windows (`Program Files`, `Program Files (x86)`, `C:\Tesseract-OCR`);
5. стандартные пути Linux/macOS (`/usr/bin`, `/usr/local/bin`, `/opt/homebrew/bin`).

Найденный путь проверяется запуском: `pytesseract.get_tesseract_version()` и
`get_languages()`. Результат кэшируется (кнопки «Проверить Tesseract» / «Проверить
окружение» сбрасывают кэш).

### 9.2. Подбор языка

`resolve_language("rus+eng", available)` оставляет только реально установленные
языковые пакеты и объясняет, чего не хватает:

```text
Запрошено: rus+eng, доступно: eng
→ используется "eng", в интерфейсе: «Не установлены языковые пакеты: rus»
```

Так программа не падает с `TesseractError: Failed loading language 'rus'`,
а честно сообщает о проблеме.

### 9.3. Подготовка изображения

`prepare_for_ocr()`:
* увеличивает слишком мелкие картинки (`min сторона < 900 px`) — Tesseract лучше
  работает с крупным текстом;
* по желанию бинаризует (Оцу) и убирает шум гауссовым размытием 3×3.

### 9.4. Распознавание и оформление результата

```python
data = pytesseract.image_to_data(prepared, lang=language, output_type=Output.DICT)
```

`image_to_data` возвращает не только текст, но и координаты каждого слова с уровнем
уверенности. Это позволяет:

1. собрать текст (`" ".join(...)`) и вывести его **в консоль** (требование задания);
2. нарисовать **рамки вокруг каждого слова**;
3. посчитать среднюю уверенность распознавания;
4. добавить **панель с текстом под изображением** (`draw_caption_panel`) — второе
   требование задания: «текст должен быть отражён на выходном изображении рядом
   с исходным текстом».

Если `image_to_data` не дал ни одного слова, выполняется резервный вызов
`image_to_string`.

Ошибки Tesseract (нет языка, нет бинарника, внутренняя ошибка) перехватываются и
попадают в интерфейс как текст, а не как «молчаливое закрытие окна».

## 10. Интерфейс: что где нажимать

Окно разделено на две части: **слева — настройки**, **справа — предпросмотр**.

### 10.1. Левая колонка

* Три кнопки-режима: **ЛР2 · Поиск объекта**, **ЛР3 · Контуры**,
  **ЛР3 · Текст (OCR)**. Переключение меняет набор настроек.
* Карточки настроек текущего режима.
* Кнопка **«Проверить окружение»** — выводит версии Python/Flet/OpenCV/NumPy,
  доступные детекторы, наличие Tesseract, список камер, доступность снимка экрана.
* **Журнал** — последние 40 событий и ошибок с отметкой времени.

### 10.2. Правая колонка

* Большое окно предпросмотра (`ft.Image`, вписывание `BoxFit.CONTAIN`).
* Строка статуса + индикатор занятости.
* Кнопка **«Сохранить результат»** — пишет PNG в `results/<режим>_<дата>_<время>.png`.
* Поле **«Подробности»** — метрики: число ключевых точек, совпадений, inliers,
  площадь/периметр контуров, NSP, уверенность OCR.

### 10.3. Сценарий для ЛР2 (статичное изображение)

1. Режим **«ЛР2 · Поиск объекта»**.
2. «Образец объекта…» → `samples/object_card.png`.
3. «Сцена…» → `samples/scene_desk.png`.
4. Источник кадра: **Статичное изображение**.
5. **«Распознать объект»** → зелёная рамка вокруг визитки + линии совпадений.

### 10.4. Сценарий для ЛР2 (реальное время)

1. Те же образец и сцена-образец (достаточно образца).
2. Источник: **Веб-камера** → «Найти камеры» (подставит индекс) или вписать вручную.
3. **«▶ Запустить поток»** → в окне предпросмотра живой кадр с рамкой, в статусе —
   число совпадений и кадры/с.
4. **«■ Остановить поток»** — камера освобождается.
5. Для слабых машин: детектор **ORB** и порог ratio 0.7–0.8.

Режим **Снимок экрана** работает так же, но кадром служит снимок монитора
(удобно «искать» объект на экране).

### 10.5. Сценарий для ЛР3, часть 1

1. Режим **«ЛР3 · Контуры»**.
2. «Сцена…» → `samples/text_page.png`.
3. (Необязательно) «Эталонный объект…» — своя фигура для сравнения форм.
4. **«Обработать контуры»**.
5. В выпадающем списке выбрать шаг обработки: исходное изображение, серое, размытие,
   бинаризация, морфология, все контуры, фильтрация, уравнивание, результат.
   Под списком показывается описание выбранного шага — это и есть «визуальное
   сопровождение промежуточных результатов» из задания.
6. Результат сохраняется кнопкой «Сохранить результат» (идеально для отчёта —
   нужны минимум 2 примера на каждую работу).

### 10.6. Сценарий для ЛР3, часть 2 (OCR)

1. Режим **«ЛР3 · Текст (OCR)»**.
2. «Проверить Tesseract» — убедиться, что путь и языки найдены.
3. «Выбрать изображение…» → `samples/text_page.png`.
4. Язык: `rus+eng` (или `rus`, `eng` — по заданию «по выбору пользователя»).
5. **«Распознать текст»**: текст появится в поле «Распознанный текст»,
   **в консоли** и **на выходном изображении** (панель под картинкой + рамки слов).
6. Сохранить результат.

## 14. Частые проблемы и решения

| Симптом | Причина | Решение |
|---|---|---|
| `ModuleNotFoundError: No module named 'flet'` | зависимости не установлены / активировано не то окружение | `pip install -r requirements.txt`, проверить `which python` |
| Окно не открывается, в консоли `flet-desktop not installed` | Flet установлен без десктопного клиента | `pip install flet-desktop==1.0.5` |
| `ImportError: libGL.so.1: cannot open shared object file` | в Linux нет системного OpenGL | `sudo apt install libgl1` |
| `error: This algorithm is patented and is excluded…` | SURF вырезан из сборки OpenCV | использовать SIFT/ORB (программа сама не предлагает SURF) |
| «Не удалось прочитать изображение» | файл повреждён, не картинка или нет прав | открыть файл любым просмотрщиком, пересохранить в PNG |
| В окне пусто, ошибок нет | **старая** версия `cv2.imread` на пути с кириллицей | в этой версии исправлено; проверьте, что запущен актуальный код |
| Камера не открывается | занята другим приложением (Zoom, Teams, браузер) | закрыть приложения, нажать «Найти камеры», сменить индекс |
| Кадр в потоке «дёргается» | SIFT на большом разрешении | выбрать ORB, уменьшить «Максимум ключевых точек», снизить разрешение камеры |
| После закрытия окна камера занята | процесс не завершился | программа освобождает камеру в `page.on_close`; при аварийном завершении — перезапустить систему/драйвер |
| «Tesseract OCR не найден» | не установлен или не в `PATH` | см. [раздел 3](#3-установка-tesseract-ocr), задать `TESSERACT_CMD` |
| OCR вернул пустой текст | слишком мелкий/шумный текст, нет языкового пакета | включить бинаризацию, увеличить изображение, установить `rus`/`eng` |
| Русские подписи превратились в `?????` | так работал `cv2.putText` | в этой версии текст рисуется через Pillow |
| Контурный анализ нашёл один большой контур | полярность бинаризации | включён `auto_invert`; при необходимости переключить «Инвертировать» |
| `ValueError: too many values to unpack` | старый код и `knnMatch` | исправлено в `ratio_test` |
| Медленно на слабом ноутбуке | SIFT + 2000 точек + большой кадр | ORB, ratio 0.7, «Максимум ключевых точек» = 800 |

Если проблема не описана — нажмите **«Проверить окружение»** и посмотрите **«Журнал»**:
там будут версии библиотек, пути и текст исключения.

## 15. Ограничения и что можно улучшить

Осознанные ограничения текущей версии:

1. **SURF недоступен** в стандартных колёсах OpenCV (патент). Теория из методички
   реализована, но сравнить SIFT и SURF «вживую» можно только в сборке OpenCV,
   скомпилированной с `OPENCV_ENABLE_NONFREE`.
2. **Контурный анализ неустойчив к пересечениям и частичному перекрытию** объектов —
   это свойство самого метода (описано в методичке), а не дефект реализации.
3. **NSP чувствителен к качеству контура.** Мелкие буквы и шумные края дают
   заниженные значения: контур из 20 точек после ресэмплинга в 64 теряет детали.
   Для устойчивого сравнения лучше брать крупные объекты или задавать эталон.
4. **Режим «снимок экрана»** работает только при наличии графической сессии
   (на headless-сервере — недоступен, программа это сообщает).
5. **OCR** требует установленного Tesseract: Python-обёртка сама ничего не распознаёт.
6. Однопоточная обработка одного видеопотока: при 4K-камере и SIFT кадры будут
   обрабатываться с задержкой (уменьшайте разрешение/переходите на ORB).

Идеи развития:

* замена `findHomography` на оценку позы (PnP) и трекинг объекта между кадрами;
* кэширование дескрипторов образца (сейчас они считаются на каждом кадре);
* сравнение детекторов в одном окне (SIFT vs ORB: время/число inliers);
* экспорт метрик в CSV для отчёта;
* распознавание контуров по коду Фримена.

## 16. Шпаргалка для отчёта по лабораторным

Что показать/описать при защите (по требованиям методичек):

### ЛР2

* **Условие задания**: программа ищет объект на статичном изображении и в потоке с камеры.
* **Ключевые функции**: `find_object()` (`src/core/features.py`), `ratio_test()`,
  оценка гомографии `cv2.findHomography(RANSAC)`.
* **Примеры работы (минимум 2)**:
  1. `samples/object_card.png` + `samples/scene_desk.png` — найдено, рамка вокруг визитки;
  2. поток с камеры (или снимок экрана) — рамка на живом кадре.
  Скриншоты сохраняются кнопкой «Сохранить результат».
* **Что говорить про разницу SIFT/SURF**: SIFT — 128-мерный дескриптор, пирамида
  гауссианов, инвариантен к масштабу и повороту; SURF — 64-мерный дескриптор,
  интегральные изображения и фильтры Хаара, быстрее, но менее устойчив к сильным
  искажениям; в предсобранном OpenCV 5 SURF отключён по патентным причинам.

### ЛР3, часть 1

* Все 7 пунктов пайплайна видны в интерфейсе как отдельные шаги.
* **Ключевые функции**: `analyze_contours()`, `resample_contour()` (уравнивание),
  `contour_to_ev()`, `scalar_product()`, `compare_contours()` (ВКФ).
* Для отчёта удобно привести таблицу по контурам: №, площадь, периметр, `|NSP|`,
  сдвиг, оценка поворота — она выводится прямо на итоговой картинке.

### ЛР3, часть 2

* Скриншот распознавания `samples/text_page.png` с языком `rus+eng`.
* Отметить: текст печатается в консоль **и** наносится на выходное изображение;
  рамки слов показывают, что именно нашёл Tesseract; средняя уверенность — в
  строке статуса.
